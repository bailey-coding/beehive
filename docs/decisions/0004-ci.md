# ADR: CI and Builds

**Status:** Accepted · **Date:** 2026-10-09

> **Audit 2026-10-17 (`docs/RECORDS-AUDIT.md`):** Verified: Workers Builds deploys, a gate Workflow and a sandbox runner exist. Not found: R2 snapshot caching (no R2 binding in any `wrangler.toml`; `docs/R2-CACHE-PRUNING-PLAN.md` is a plan). GitHub Actions `ci.yml` and `ci-enhanced.yml` now run typecheck, unit tests and clean installs on GitHub; this ADR does not mention them (AGENTS.md rule 6 does). `docs/ARCHITECTURE.md` indexes this ADR as "CI (Workers-only)".

Use Cloudflare's **CI SDK pattern**: Workflows + Sandbox SDK, each pipeline step in its
own sandbox, R2 snapshot caching between steps (candidate install steps can warm-start
from the baseline's snapshot). Same sandbox abstraction serves agent execution and CI —
one runner codebase, two entry points. Workers Builds owns deploys (Preview per candidate
branch). Constraint: no nested containers (Docker-in-Docker) — irrelevant for the TS
candidate services, blocks container-image builds as candidate artifacts.
